# Backend API client

Use generated contract types and a thin client. Keep authentication and authorization enforced on the server. The customer-facing client exposes read-only search, opportunity, evidence, contact, buying-chain and autonomous research projections; it does not expose manual call logging, fact drafting, operator status, contact corrections, pursuit notes or research submission controls.

Current opportunity browsing uses `client.opportunityGroups` and `client.groupProjects`: source-backed operator/customer groups form the primary list, with bounded project pages nested beneath each group. Parent pages and each expanded child page use separate cohort tokens; every child request includes its parent cohort token, and a 409 clears the stale group and project state before refreshing. Project detail still refreshes the exact prepared physical-project result before exposing contact controls. Existing need detail, account, Signals and Research clients remain secondary. See [the prepared project contract](../../../docs/architecture/PROJECT_RESULTS.md).
