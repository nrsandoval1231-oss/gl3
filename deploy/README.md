# Deployment artifacts

Files under `deploy/` are implementation/build artifacts or alternate deployment preparation. They are not the actual production runbook. The November 2 release is deployed from immutable images under `/opt/gridlens/releases/<tag>` using the protected host controller and existing protected configuration. See the [operations authority](../docs/operations/README.md) and [November 2 production release record](../docs/validation/production-release-20261102.md) for the exact accepted images, schema, verification and limits.

This release receipt establishes only its dated images and observed runtime. It does not establish future runtime state or authorize another production operation. The repository's newer wrapper companion is not established as installed on the host. Use [local runtime](../docs/operations/local-runtime.md) for native or Compose development. `deploy/digitalocean/README.md` remains alternate preparation and must not be executed against the observed host.

The repository nginx configuration denies embedding the standalone app through `Content-Security-Policy: frame-ancestors 'none'` and `X-Frame-Options: DENY`, including error responses. This narrow CSP does not restrict scripts, styles, fonts or API connections. Existing navigation and source links do not require framing. Local configuration tests do not prove these headers are deployed; inspect actual response headers after a separately authorized release.

Cache and compression policy requires attribution to the serving layer before changing configuration. The October 30 public audit observed fingerprinted JS/CSS delivered with `Cache-Control: no-store` and no content encoding, including normal browser requests advertising compression. That observation passed through the managed proxy and Caddy; the actual host/edge configuration was unavailable. Repository nginx has no explicit asset cache or compression policy, but that does not identify the source of the live headers. Inspect the effective origin/edge/proxy configuration and compare encoded and decoded response sizes before selecting a change. Consider immutable caching only for public fingerprinted assets and compatible compression after attribution; preserve private API/auth and HTML caching boundaries. No cache or compression change is made here.
