# Other sectors and regulation (workstream 5)

**Date:** 2026-11-04 · **Code:** `ingestion/adapters/{sector_common,faa_oeaaa,msha_mines,tceq_aggregate,afdc_stations,nevi_awards,sec_edgar_site_mw,ercot_monthly,regulatory_events}.py`, `config/regulatory/events.v1.json` · **Source IDs:** `faa-oeaaa-obstruction`, `msha-mines`, `texas-tceq-aggregate-production`, `afdc-ev-stations`, `texas-txdot-nevi-awards`, `sec-edgar-site-mw`, `texas-ercot-monthly-overview`, `regulatory-event-feed`

This is section 5 of the [ingestion handoff](../strategy/ingestion-handoff-20261103.md). Eight sources, each its own adapter and registry entry, **all shipped off** (`enabled: false`). Nothing was deployed, no credential or paid provider was used, no migration was added, and the one-off live checks below are not evidence that anything works in production. Activation steps are in the [workstream 0 note](../strategy/ws0-production-env-changes-20261103.md#workstream-5-sector-and-regulation-sources-activation).

Rules held throughout: evidence or nothing (verbatim quote, record identity and location with every value); unknown is never zero; documented, calculated, estimated, inferred and unknown stay distinct; supply stays apart from demand; at most one request per second with the declared generic user agent; exact https host allowlist, no redirects, byte caps, media-type allowlist; `first_seen_at` is never rewritten (the existing ingestion service owns it); `first_seen_at` and `observed_at` are set for every record by the ingestion service. `published_at` is filled only where the source states a publication date: FAA (determination date), AFDC (`updated_at`, when present), TxDOT NEVI (`PUBLISHED`, when present), SEC (filing date), ERCOT (the date folder of the PDF URL) and regulatory events (the statement date). **MSHA and the TCEQ aggregate registry state no publication date, so their `published_at` stays NULL** (they carry an event date: the MSHA status date, the TCEQ last application status date); nothing is inferred from the fetch time. A test asserts this per kind.

## What a record from these sources means

None of these sources states a site load. Each record is evidence about proximity, registration, an award, an aggregate or a dated official statement. They reach the ingestion service through the existing permit-shaped record contract with `data_center: false` and no power-signal tag, and `permit_interpretation._EVIDENCE_ONLY_SOURCE_TYPES` makes the assessment always **rejected / stays evidence** even when a sponsor or facility name contains the words "data center" (tested). They create no need, project or card, and no admission rule exists for them; the integration test counts zero `PowerNeed` and `Project` rows after ingesting every kind.

**Diff.** New and changed records are found by the service's existing record-hash change detection, not by a snapshot kept in these adapters: each record's `source_hash` covers the stated fields only (never the file date, fetch time or row order), so a weekly or daily replay creates nothing for an unchanged record, a changed-version event for a changed one and a new observation for a new one (integration test with a week-over-week MSHA change, an added mine and an award status change).

**Rate limits.** The first `429` or `503` with a long `Retry-After` is raised as `httpx.HTTPStatusError`; the worker's existing diagnostics store `http_status_429` and the retry hint, and nothing in these adapters retries it again (one request in the unit test). The shared helper makes a **single attempt** per request (no in-run retry of a 429 or 503, which would ignore `Retry-After` and the one-request-per-second pacer), and resolves the host immediately before each request, refusing it unless every address is public (`is_global`; the same helper the TCEQ readers use). That is a check per request, not a connection pin: a DNS answer that changes between the check and the connect is not caught. The job deadline is passed to the pacer, which stops the run once it has passed.

## Design by source

### 1. FAA OE/AAA (`faa_oeaaa.py`)

One request per determination day for the last `window_days` days (1 to 7), each capped at `max_response_bytes` (12 MB) and parsed with DTDs and entities refused. A day that returns 8,000 cases or more **fails the run** (it may be incomplete) rather than being treated as complete; the day-by-day window keeps typical days near a quarter of the cap. The spatial join is deterministic: a case is a candidate when its stated coordinate lies within `radius_m` (50 to 10,000 m, shipped 2,000) of an owner-listed campus by haversine distance on a sphere of 6,371,008.8 m, inclusive at the edge, candidates ordered by distance then campus id. A candidate records the ASN, structure type and height, sponsor as filed, dates, status and the campus distances, and says in its text that it is proximity only. **The campus list ships empty** (no campus coordinates were verified for this note): with no campuses the reader makes no request and returns nothing.

### 2. MSHA (`msha_mines.py`)

Registered with `cadence_hours: 168` (validated), one download per run, 15 MB compressed cap by `Content-Length` and streamed count. The archive is untrusted: exactly one non-directory, unencrypted member named `Mines.txt`, a declared size cap (60 MB shipped, 80 MB maximum), a compression-ratio cap of 30 (the real file is 5.4), a streamed read bounded by the cap and checked against the header size, nothing written to disk, no nested archive. Rows are filtered to the configured states and statuses (TX, OK, NM and Active, New Mine, Intermittent, Temporarily Idled, NonProducing, 1,335 rows live), capped at `max_records` (3,000), and keyed `MSHA-<MINE_ID>`. A missing or duplicate mine id fails the run. Dated by the current status date.

### 3. TCEQ aggregates (`tceq_aggregate.py`)

A `count(*)` query, then 500-row pages ordered by `registration`; the pages must add up to the count, the count must be within `max_records`, and registrations must be unique, or the run fails. Dated by the last application status date, else the registration start date.

### 4. AFDC (`afdc_stations.py`)

Host `developer.nlr.gov`. Key from `Settings.afdc_api_key` (`AFDC_API_KEY`), header only; missing key is a typed failure **before any request**. TX, OK and NM, open/planned/temporarily unavailable, 200-row pages with an offset, count-checked against `total_results`. Port counts are counts, not kW; a missing count is `None`, never 0.

### 5. TxDOT NEVI (`nevi_awards.py`)

Count-checked 500-row pages of the public layer, ordered by `OBJECTID`, fixed field list, no geometry. **Calculated nameplate** is ports times the stated maximum per-port kW (for example 6 x 200 kW = 1,200 kW), labelled calculated and "a rating, not site demand", and unknown if either is missing. Dates are `M/D/YYYY` strings, `--` is unknown. Texas only (see the ODOT finding).

### 6. SEC EDGAR site MW (`sec_edgar_site_mw.py`)

Owner-listed CIKs (ships empty, at most 10), newest 10-K/10-Q per CIK from the submissions index, document name and accession validated before the URL is built, 12 MB cap per document. **It refuses to run until the owner sets `SEC_EDGAR_CONTACT`** (the contact is appended to the generic user agent in parentheses; the repository holds no personal address). Extraction keeps only a single sentence of the filing's own text that ends in sentence punctuation, contains a MW/GW figure and names exactly **one** site ("... Facility/Campus/Data Center/Site/Project/Plant"). Energy units (`megawatt-hours`, `MWh`, `GWh`) are not power figures; financing instruments ("Revolving Credit Facility", "Term Loan Facility") are not sites; a sentence naming two sites is dropped rather than attributed to the first. Text inside table cells (`td`, `th`) and hidden iXBRL header text is never read, so a table yields nothing. The verbatim sentence, accession and the character span **in the extractor's normalised text** are stored (the span is checked against that normalised text, not against the raw HTML, so it locates the quote only by re-running the same normalisation). Rows are keyed by CIK, accession and a hash of the quote; accessions that already have observations are not fetched again (the service passes them in; a filing that produced no statement is re-fetched each run, within its one-per-CIK bound). The contact is held as a secret, must be printable ASCII and is never echoed. The sentence is not classified (capacity versus load versus target is left to the quote). Dated by filing date (published) and report period (event).

### 7. ERCOT monthly (`ercot_monthly.py`)

Board page, then the newest `max_reports` (2) linked overview PDFs (6 MB cap each). If two PDFs report the same month (a revised issue), only the one with the newest posted date is kept. The record is the ERCOT-wide approved-to-energize and observed non-simultaneous peak MW from the quoted sentence; the sentence's month must equal the report month or the figures are unknown; the ratio is calculated from the two stated numbers. No location is emitted and the text says it is not a site or customer. Registered weekly.

### 8. Regulatory event feed (`regulatory_events.py`, `config/regulatory/events.v1.json`)

No network. Each event: id, date, issuer, official source URL (https, `gov.texas.gov` or `www.tceq.texas.gov`), verbatim quote, a fixed `effect`, a scope (state, agency, subject, instrument) and the date it was verified. The model is event -> affected scope -> status label through a fixed table: `pause_directed` (the Governor's 2026-09-21 letter) -> **no label**, because a directive to pause is not a statement that any filing is paused; `pause_screening` (TCEQ's own 2026-10-19 reply, which says staff are screening pending applications and pausing those subject to the directive) -> "pending — pause may apply (TCEQ screening)"; `audit_required` -> "pending — audit required"; `lift_pause` and `conditional_ineligibility` -> no label. The audit order's scope is agency `PUCT+ERCOT`, instrument `project_advancement`, because its quote says no data center project "moves forward" and does not mention interconnection. `status_for(filing, events, as_of)` returns a label only for a filing that **itself is explicitly a data-center project and pending**, in the matching state, agency and instrument, on or after the event date; the latest event in that scope wins, and only a later `lift_pause` clears a pause. Nothing infers an end date, a decision on a single filing or that a missing permit means anything. A unit test checks every quote against the saved text of its official page (whitespace-insensitively only for the TCEQ PDF, whose text layer has stray spaces). The function is not wired to any output yet; the feed records are what ingestion stores.

## What was tested

Unit (`tests/unit/test_sector_sources.py`, mock origins, real-derived fixtures in `tests/fixtures/ws5/`, the unit file): ships-off and registry bounds; no `nrel.gov` URL in code or config; URL policy and SSRF (redirect never followed, foreign host refused before any request, wrong endpoint or id refused); pacing at one request per second; 429 with `Retry-After` ends the run after one request and the diagnostics read it; evidence-only assessment even for a sponsor named "... Data Center"; FAA join (nearest first, tie order, radius edge, per-day windows, cap, DTD, byte cap, media type, empty campus list makes no request); MSHA (scope, hash stable across file date and row order, one download, zip guards: wrong name, two members, traversal name, ratio bomb, oversize, not a zip, content-length cap, duplicate id, record bound); TCEQ (count and pages, diff, mismatch, duplicate, bound); AFDC (no key means no request, key in header only, paging, bad shape, 403); NEVI (identity, nameplate calculated and unknown, mismatch, duplicate, error payload, fixed paging); SEC (no contact means no request, contact in user agent, quotes and spans, hidden text, no site means nothing, 403, path-traversal document name dropped); ERCOT (links, parse, unknown not zero, month mismatch, two requests only); regulatory events (quotes in official text, the status table, lift, validation).

Integration (`tests/integration/test_sector_sources_ingestion.py`, disposable PostgreSQL `_test` database, separate schema): MSHA week one, identical replay (all unchanged), week two with one changed and one new mine (counts 1/1/5, `first_seen_at` untouched, evidence versions), every other record kind ingested and replayed idempotently with dates present and zero `PowerNeed` or `Project` rows, a changed award adds a version, a 429 leaves prior evidence untouched.

## Open risks and what could not be verified

- **AFDC response shape is unverified** (no key). The parser follows the published field names and fails closed on a different top-level shape; the first enabled run needs a look.
- **FAA**: no current guide exists (404), so parameters beyond `start`/`end` are unknown; the 8,000 cap is confirmed only as "8,001 returned". The campus list is empty, so enabling does nothing until the owner lists campuses; matching to a campus says nothing about the operator.
- **SEC**: needs the owner's contact; sentence boundaries are heuristic (a sentence can run on across an abbreviation), the site name is the capitalised words before the site noun, and table cells are skipped. Registrant coverage is the owner's CIK list. A filing that produced no statement is fetched again each run.
- **ERCOT**: depends on one sentence in a PDF and on the Board page listing; a reworded sentence yields unknown, not a wrong number. The Board page lists 2026 issues only.
- **NEVI**: the layer has placeholder rows and blank ids; rows are keyed by CSJ plus coordinate, so a moved site would be a new site. Oklahoma has no machine-readable awards.
- **MSHA**: 1,335 first-run records; the first enabled run ingests all of them as new. The register holds no equipment or demand.
- **Regulatory events** are hand-maintained and cover Texas only; the pause has no stated end, and none is assumed.
- The shared ArcGIS host `services.arcgis.com` is allowed for the NEVI path only through the registry endpoint check; the adapter itself pins the exact host and the query path.
- Not run live end to end: no adapter was run through the real worker; the checks above used the same code over real responses fetched one at a time.
- **Alerts and first-signal samples.** These sources are evidence only: they must be **excluded from new-signal alerts and from the retained first-signal sample** before MSHA (about 1,335 first-run records) or any other source here is enabled alongside the workstream 6 changes. The workstream 6 code is not on this branch's base, so that exclusion is a follow-up for the workstream 6 branch (filter on `Observation.source_id` in the evidence-only set, or on `permit.source_type` in `permit_interpretation._EVIDENCE_ONLY_SOURCE_TYPES`).
