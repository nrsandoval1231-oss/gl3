# Intelligence Phase 0 repository audit — 2026-10-29

**Status:** dated repository audit; describes observed code and documentation at this checkout, not a production re-audit. **Authority:** product direction is in [Autonomous Intelligence Canon](../product/AUTONOMOUS_INTELLIGENCE_CANON.md); this document records evidence and gaps only. **Scope:** implementation, schema, providers, UI, operations and delivery boundaries inspected in `gl3`. No code or retained data was removed as part of this audit.

## Executive finding

The repository already has a substantial evidence-preserving project intelligence system: configured source adapters, a scheduled/fenced worker, versioned PostgreSQL records, deterministic qualification and commercial projections, bounded research/enrichment, and an authenticated React client. The checkout does **not** demonstrate the canon's complete target platform. In particular, a general equipment-to-demand model, broadly reusable lifecycle/equipment/scenario graph, independent end-to-end verification policy, consolidated commercial buyer opportunities, and measured policy/model promotion are not evidenced as complete end-to-end capabilities. Treat those as target gaps, not shipped features. The most defensible first slice is a source-backed equipment/load evidence contract plus one bounded Oil & Gas fixture cohort, after schema and entity-linkage design.

The current production checkpoint is a dated owner-maintained receipt in `.agent/CURRENT_STATE.md`, which reports PR148 and application SHA `ca12443f5c57f3502584d8a353d83cdf7d5372b1`, schema 0049 / 74 tables, and a successful release check. This audit did not access live production, verify that receipt, or infer that this checkout is the deployed revision.

The safe Phase 0 cleanup is authority consolidation in maintained docs: link active guides to the canon, label current versus target, and route superseded material to clearly marked history while preserving it. ## Highest-leverage first implementation slice

**Slice 1: additive, source-traceable equipment and demand claim contract for one Oil & Gas activity cohort.** Specify a typed claim with project/activity binding, source/evidence identity and hash, observation/retrieval time, extraction/calculation version, drive type, electrical input basis, connected/operating assumptions, scenario bounds, explicit unknown/conflict state, and deterministic recomputation. Map existing evidence and project identities without changing qualification or publication behavior. Add a small labeled fixture set for electric drive, gas drive, uncertain drive, standby/redundant equipment, conflict and missing load. This yields a reusable evidence foundation and proves the critical “equipment does not silently become electrical load” boundary before widening to Data Centers or autonomous publication.

**Prerequisite:** map existing `PowerNeed`, `NeedObservation`, `Evidence`, `Interpretation`, project identity and accepted-evidence relationships to avoid duplicating current structures. Confirm migration/test harness and isolated database procedures. Do not activate paid providers, change production data, or alter current Lead rules in this slice.
