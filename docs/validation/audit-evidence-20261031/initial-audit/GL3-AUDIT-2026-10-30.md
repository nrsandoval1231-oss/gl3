## Severity-ranked findings

### F1 — P2: Company/Project sort silently sorts only the loaded page

**References:** `web/src/features/workspace/CanonicalOpportunityResults.tsx:106`, `:150`, `:161`; `backend/src/gridlens/api/app.py:2052`.

The request always uses `sort=priority`; Company/Project selections reorder only the current25 items in memory. The UI labels this `Sort opportunities`, without explicitly explaining that sort is page-local. API currently exposes priority/updated sorting, so changing the UI alone cannot produce corpus-wide Company order.

**Reproduce (isolated mocked browser):** provide26 records, first25 belonging to Zebra and the26th to Aardvark. Select Company, inspect first row on page1, then Next. Zebra remains first on page1 while Aardvark appears on page2. Requests on both pages retain `sort=priority`. Project sort has the same mechanism.

**Evidence:** `/workspace/audit-evidence/frontend/reproduce-final.json`, `/workspace/audit-evidence/frontend/reproduce-final.mjs` , `/workspace/audit-frontend.md`. Independent reviewer confirmed request and rendering logic in `/workspace/audit-independent.md`.

**Impact:** users cannot reliably browse the alphabetically first company/project, and may mistake a sorted page for globally sorted results. No real customer data was used and no live authenticated reproduction is claimed.

**Recommendation:** add server-owned company/project sort with deterministic tie breakers and cohort-compatible pagination, include sort in request/cache/URL state, and reset offset on changes. Alternatively clearly label the control `Sort this page` until global sorting exists.

### F2 — P2: RRC flare refresh cannot recover missed submission windows or later status changes

**References:** `config/sources/registry.v1.json:27-34`; `backend/src/gridlens/ingestion/adapters/rrc_flare_exceptions.py:282-283`.

Enabled daily acquisition always queries today and the prior two calendar days by **submission date**. It does not advance from a last-success cursor. A filing submitted outside that window will not be rechecked when its status changes; a sufficiently long outage leaves an unrecoverable ordinary-refresh gap. This limitation is explicitly documented in the registry and is not a newly introduced regression or proof of an actual stale live filing.

**Reproduce:** inspect configured `window_days=3`; evaluate adapter start date after a four-day collection outage. The missed filing's submission date is outside `[today-2,today]`, regardless of last successful check. A status change today to a four-day-old filing is likewise excluded by the submission-date query. Source-specific unit tests were freshly executed; independent review confirmed the date-window logic.

**Impact:** application/authorization state and discovery completeness can diverge from official source state following interruptions or later decisions. Do not infer physical flaring, generator fit, MW or buying authority from these applications.

**Recommendation:** separately bounded missed-window catch-up and retained-ID status monitoring, durable checkpoints and explicit freshness/coverage diagnostics; tests for outage, late status change, pagination and idempotent replay. Do not execute a backfill as part of this audit.

### F3 — P3: Empty page filters produce an impossible pagination range

**Reference:** `web/src/features/workspace/CanonicalOpportunityResults.tsx:180`, filter logic `:147-150`.

**Reproduce:** with26 projects, page1 is Midland and page2 is Dallas. Go Next, select Dallas Region, then Previous. Region remains selected, page1 has no visible matches, and footer displays **`1–0 of 26 projects`**. The local browser reproduction captured this exact text.

**Evidence:** `/workspace/audit-evidence/frontend/reproduce-final.json`, `/workspace/audit-evidence/frontend/filter-empty-page.png`; independently accepted.

**Impact:** misleading count/range and empty page despite a nonzero corpus; the user cannot tell current-page matches from original page positions. Region/stage/priority are explicitly labeled page filters; their page-local scope itself is not reported as a backend filtering defect.

**Recommendation:** show `0 matching projects on this page` when no visible rows, and separately describe underlying server page range/total. Keep consistent units when filtering a subset.

### F5 — P3: Public sign-in shell can be embedded cross-origin

**References:** `deploy/nginx.conf:1-20`, especially `:17-19`; live response `/workspace/audit-evidence/live-headers.txt`.

No CSP `frame-ancestors` or X-Frame-Options is present. A local browser page at intercepted origin `http://audit.invalid/` successfully displayed the real public GridLens sign-in page in an iframe. No login attempt or credential entry occurred.

**Evidence:** `/workspace/audit-evidence/live-frame.json`, `/workspace/audit-evidence/live-iframe.png`, reproduction `/workspace/audit-evidence/frame-check.cjs`.

**Impact:** public shell/sign-in can be placed in a deceptive frame. This is a hardening gap, not demonstrated authenticated clickjacking, credential theft or data access. Strict SameSite cookies reduce authenticated cross-site exposure.

### F6 — P3: Public static delivery refetches uncompressed assets on warm navigation

**References:** live `/workspace/audit-evidence/perf-js-headers.txt`, `perf-css-headers.txt`, `performance-public.json`; repository `deploy/nginx.conf:17-19` has no explicit compression/cache policy, but actual edge ownership is unverified.

**Reproduce:** three cold/warm browser pairs at each desktop/mobile viewport. Every sample reports963,681B of subresource transfer, including the same422,484B JS and101,750B CSS on warm loads. HEAD requests offering gzip/br return `Cache-Control:no-store` and no Content-Encoding for fingerprinted JS/CSS; Resource Timing encoded/decoded lengths agree. A further unmodified browser navigation confirmed actual browser requests send `Accept-Encoding:gzip, deflate, br, zstd` and receive full-length200 responses with no Content-Encoding and `no-store` (`browser-delivery-headers.json`). Inter/Sora fonts add399,700B. The fresh Vite build estimates gzip JS122.08kB/CSS17.55kB.

**Impact:** about385kB of avoidable JS/CSS transfer per navigation relative to build gzip estimates, plus ineffective versioned-asset reuse. Observed public loads were still subsecond in most samples; no general slow-site or authenticated performance claim is made.

These observations are through the managed HTTPS proxy. An intermediary may affect negotiation, headers or caching; the origin configuration and responsible layer were not independently verified. This is a confirmed delivery-path inefficiency, not a uniquely attributed origin defect.

**Recommendation:** inspect the actual edge/Caddy/nginx configuration, compress text assets, and allow immutable caching for public fingerprinted files while retaining appropriate no-cache policy for HTML/private API/auth responses. Profile font subsetting/sign-in bundle needs separately. No changes applied. Full methods and limits: `/workspace/audit-performance-public.md`.
