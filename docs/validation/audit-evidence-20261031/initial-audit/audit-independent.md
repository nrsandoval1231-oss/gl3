## Findings reviewed independently

### Medium/P2: rolling RRC source windows do not provide outage recovery or later-status freshness

Confirmed ingestion reviewer finding independently from `config/sources/registry.v1.json:27-34` and `backend/src/gridlens/ingestion/adapters/rrc_flare_exceptions.py:282-283`. The adapter always computes start as today's date minus configured window minus one; registry uses three calendar days. Reproduction is deterministic: a submission dated dayD is queried onD,D+1,D+2, and excluded atD+3; a status update or first successful run after that point cannot retrieve it by ordinary acquisition. No last-success checkpoint is used in this function. The limitation is explicitly documented; it remains a functional recovery/coverage limit even though it is not newly introduced. No actual missing or stale production filing was verified. Impact: discovery gaps after outages and stale authorization context for older filings. Fix: reviewed bounded catch-up and retained-ID status refresh with explicit health/coverage outcomes, never infer actual flaring or MW from applications.

### Medium/P2: Company/Project sort is local to the fetched page

Independently confirmed frontend review candidate. `web/src/features/workspace/CanonicalOpportunityResults.tsx:106` always fetches server `sort:'priority'`; line150 sorts only `items` from the fetched25-project page. The UI offers Company and Project under `Sort opportunities` at line161. Backend `api/app.py:2044-2053` accepts only priority or updated and `project_results.py:35-43` binds sort to cohort identity. Thus a company alphabetically earlier on page2 remains behind all page1 companies after selecting Company. Repro on synthetic pagination: place Zulu on priority page1 and Alpha on priority page2, select Company, and observe Zulu still on page1. Main frontend reviewer owns direct browser reproduction; this lane provides independent source validation. Impact: misleading cross-page ordering and inefficient organization lookup. Fix: implement cohort-wide company/project ordering with stable tie-breakers and sort-specific pagination/cache tokens, or explicitly label the existing option as sorting only this page. Page-filter scope copy at line163 names region/stage/priority, not sort.

### Low/P3: filtered empty later page can display inverted range

With offset25 and a page filter matching0rows, it renders26–25 ofNprojects. The page filter legitimately only affects loaded items (line163 says this), but displayed range should not be inverted. Main frontend lane owns browser reproduction. Fix: show0matching projects on this page or use fetched page range with a separate visible-match count.
