## Confirmed repairs

1. **Historical alias privacy.** A Pursuit can be retrieved through a canonical need in a different project. Saved free text now uses the entire historical alias-connected project cohort, regardless of assertion state. Bounded frontier queries cap needs and assertions, preserve retracted/transitive scope, and fail closed within savepoints. The same protection applies to list next tasks and detailed/mutation responses. Stored notes, tasks and activity remain unchanged.
2. **Account child order.** Initial and subsequent child pages retain the generation-bound account query's order after shared project serialization. Tests cross persisted legacy rank against shortlist relevance and exercise priority, ascending priority, company and update sorts across multiple pages.
3. **Header restoration.** Pursuits to Opportunities restores the selected need and section as well as URL context. Back returns to the account instead of the intervening Pursuits page. Repeated header navigation, browser Back/Forward and reload retain loaded child pages.
4. **Membership refresh.** Independent adversarial review found that restored details could retain old account validation while new membership was pending. Navigation, history, session expiry and detail refresh now discard that trust synchronously or at read startup. Desktop/mobile regressions delay a changed-membership response, require private account actions to be absent even in hidden DOM while pending, and verify the stale selected account context is removed afterward. Unrelated ordinary account cards remain browsable.
