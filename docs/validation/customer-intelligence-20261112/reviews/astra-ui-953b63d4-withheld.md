## Material findings

1. **Verified name-only account contact disappears when a commercial brief exists (P2).** In `ProjectResults`, the featured project's `commercial_brief` branch renders `CommercialBriefSummary` instead of `FeaturedContact`. The former requires an actionable `href` and ignores the authoritative account contact's verified people. An account can therefore have a permitted, employer-matched named professional in `account_contact_project`, yet show no contact on its main card. The current screenshot fixture omits `commercial_brief`, so it misses this common branch. Independent browser diagnostic: `cardShowsName=false`, `detailShowsName=true` with the same authoritative contact. Preserve authoritative null and employer/source filtering when repairing this; do not recover a rejected contact through fallback.

2. **Conflicts and timeline meaning disappear in account detail (P2).** `capacity.conflicts` is never rendered. The generic timeline `show()` omits `event_type`, `status`, `scope_id` and conflict `claim_ids`; backend-shaped conflict objects render empty paragraphs. The browser diagnostic supplied conflicting 20/40 MW claims and conflicting Q2/Q4 expected construction targets for phase 1. Expanded detail displayed only unavailable-total/timeline wording and the two date labels, without the conflict reason, phase or expected status. The card's generic next action does mention conflict, which is a partial safeguard; it does not supply the missing detail evidence. Render explicit conflict/overlap state and trace each alternative to its scoped claim and source, preserving actual-versus-expected and construction-versus-energization distinctions. Raw interval bounds must not become exact public dates.

3. **Positive commissioning scenarios lack their engineering trace in the UI (P2, static finding).** The model provides `commissioning.input_evidence`, `calculation_version`, assumptions and input/config digests. The component renders numeric bounds and limitations only. Top-level `intel.sources` is populated from capacity/timeline claims, so an engineering-only positive scenario has no engineering source link in this view. Add progressive engineering evidence and assumptions/model disclosure. A base-only estimate should be labeled as a base value rather than displayed as an apparent `X–X` range. No positive engineering scenario was present in the committed screenshots, so they cannot verify this path.

4. **Visible rendering defects (P3).** The account-detail screenshot contains a standalone `0` after Sources because `(claims.length || conflicts.length) && …` evaluates to numeric zero for empty arrays. Name-only contact text runs together as `Facilities DirectorVerified project responsibility...unavailable.Contact source`, confirmed by browser text extraction. Fix boolean conditional rendering and explicit block/spacing structure.
