# Incremental RSS retrieval and migration parity (C2)

The bounded publisher RSS adapter now preserves the ordinary two-value bounded
HTTP helper contract and can opt into a typed status result for conditional GETs.
It stores ETag/Last-Modified metadata under the source health namespace
`publisher_rss_conditional` only after a complete parse and retained collection
batch. The cache key includes endpoint, source query/policy, parser version,
retained-news evaluator version, and admission policy version. Disabled sources,
changed versions/policy, forced reprocessing, and incomplete Job checkpoints do
not reuse validators.

A valid 304 updates only the check timestamp and preserves the last complete
snapshot facts; it does not run collection processing or create evidence,
withdrawals, or model work. Invalid/empty 200 responses and interrupted batches
leave the last-good validator untouched. The RSS path releases a clean prepare
transaction before bounded HTTP and refreshes the enabled source and policy
before writing; the worker rechecks current source/job state before completing.
The existing RSS host allowlist, no-redirect behavior, timeouts, and byte limit
remain in effect. No provider or live external HTTP call was made in validation.

The ORM now matches migration 0026: `jobs` declares the active
`project_monitor` partial index and `project_monitor_watch_sources.id` uses
`BIGINT GENERATED BY DEFAULT AS IDENTITY` metadata.
