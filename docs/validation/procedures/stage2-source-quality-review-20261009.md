# GL3 Stage2 authentic record sampling procedure — frozen before native requests

## Scope and freeze
This procedure applies to the six enabled Texas priority routes in the Stage2 packet. Freeze timestamp and file SHA-256 are recorded in the Stage2 private run manifest before the first native request. It does not alter source query bounds or product policy.

## Candidate pool and deterministic order
After each selected source check and its unchanged replay, export the full set of distinct authentic Observations visible in the isolated corpus for each source, with stable source ID, stable observation/source-record ID, immutable Evidence ID/hash/version, pipeline admission and current presentation state. Do not drop rejected, stale, unresolved, lower-tier, or null-date rows. Retained baseline rows and Stage2-fresh rows stay labeled separately with original acquisition/retrieval metadata. Duplicate source versions are one candidate observation; version history is retained as context.

Within each source, order candidates by ascending lowercase SHA256 hex of UTF-8 `source_id + stable_record_id`; ties break by stable_record_id bytewise. The hash order is used for unbiased selection only; judgment is not known at selection time. Stable IDs are the adapter's official record key or observation's persisted source_record_id, never project display names.

## Target and balancing
Target 36 records, six per route when available. For each route, select the first six in hash order, while reserving one slot each for admitted, rejected, and ambiguous/unknown pipeline outcomes where those strata exist: take the earliest hash-ranked member of each present stratum, then fill remaining slots in overall hash order without duplicates. If a route has fewer than six distinct records, take all; redistribute the deficit among available routes by repeatedly selecting the next overall hash-ranked unselected record from successful routes, preserving each route's strata reservation. Report each route's full candidate count and any inaccessible route/empty stratum. If fewer than 30 genuine records are accessible across baseline plus fresh sources, do not manufacture or substitute records; state the blocker.

## Hard-case tags (multi-label, based only on source and stored facts)
Before deciding correctness, independently tag records with any applicable condition: oil/gas well or flare application; campus or existing facility; standby/generator/nameplate language; permit authorization where active work is unproved; construction/commissioning versus operation; temporary/rental power versus fixed infrastructure; missing or null publication/event date; duplicate/revision/republish identity; potentially inherited buyer/contractor; conflicting or weak project/site identity; unknown MW, utility supply, gap, start, duration, buyer role, or authority. Include all hash-selected tagged cases; do not replace them with cleaner records. Lower-priority but valid well Signals and unknown utility/gap are not automatically false-positive admission.

## Human review rubric and metric denominators
Review every selected record. Cite official source URL and record ID, exact evidence hash/version and location, source-supported identity/site/activity, event/publication/retrieval dates (or explicit UNKNOWN), persisted grouping and presentation, and whether a next commercial question has an evidence-supported buyer path. Classify each defect as acquisition, extraction, identity, qualification, presentation, or absent evidence. Count each metric over all selected records; retain numerators, denominator, record IDs and UNKNOWN members. Separate (a) factual identity/activity/date/evidence correctness, (b) incorrect Signal admission claims (only unsupported identity, activity, current-work, or qualification claims), (c) lower commercial usefulness/priority, (d) missed useful information, (e) duplicate/grouping errors, (f) buyer-path usefulness, and (g) unknowns blocking action. Missing utility, MW, gap, buyer authority, or event date stays UNKNOWN and is never inferred. Report recall only against evidence actually present in authentic sampled source material; distinguish absent evidence from pipeline misses.

## Shortlist
A pursuit candidate must be in the evaluated set and cite source-backed direct user/responsible-contractor organization and role evidence plus a concrete discovery question. Permit authorization alone does not prove active work; campus/standby/nameplate does not establish temporary demand; missing utility data is not a gap. Raw well/flare applications alone do not establish fixed O&G power projects. Prefer supported Texas data-center construction/commissioning/bridge cases; allow valid lower-priority Signal admission while excluding intermediaries and unsupported demand/supply/buyer claims. No invented contact, package, MW, lead, or outreach.
