## Source admission and terms boundary

Observed source checks are: registered acquisitions use selected `Source`/`Observation` rows and an exact registered native endpoint; external retrieval is finite and URL-validated; extraction output is only a candidate document passed to normal retained research admission; each question rechecks its canonical need, project identity, selected-source fingerprint and fencing token before persistence. Provider discovery snippets are discarded; only deduplicated public URLs are returned. Cross-question result reuse does not bypass the requesting question's retained-evidence, privacy/suppression, identity, budget, or fencing gates. Direct public access now requires one active exact-host approval record with a nonempty terms-review reference, reviewed timestamp, expiry, allowed `direct` mode, and no revocation. The reference is an owner attestation; code does not decide whether the review itself is legally sufficient. The direct adapter then reads that host's `/robots.txt` without redirects, applies conservative exact-agent/wildcard rules, and denies on missing, malformed, unsupported, or error policy responses except allowed `404/410` absence. The same pinned public IP is used for robots and target request.

This checkout includes the site-policy helper and the worker integration. Deterministic helper tests cover exact-host/mode/expiry/revocation, robots parsing/statuses, callback budget exhaustion, redirect denial, DNS rebinding, and private-address rejection; worker integration tests cover default-deny before direct transport and robots+target budget accounting on an approved synthetic test host. Search metadata remains separate and does not submit `scrapeOptions` or automatically fetch SERP pages. Firecrawl extraction remains internally blocked because its target redirect/private-host controls are unverified. No real host approvals are configured by this lane. Code-level terms reference and robots checks do not establish that a current operator has reviewed a given publisher's terms; each activation needs a real exact-host review record for the authorized mode and retention/privacy configuration.

Any later separately authorized source/provider activation requires exact-host terms review and robots evaluation for each destination, approved mode, expiry and revocation handling, privacy/retention review, and a bounded cost authorization. This audit did not perform those operational reviews and does not authorize activation.

No paid smoke test is authorized here. If separately authorized later, it must use a designated credential and an owner-approved per-call and total cap, one non-sensitive public URL/query, record provider's billed usage alongside local upper-bound reservations, and verify the result/receipt without promoting unsupported evidence. Current Phase 2 acceptance continues to use mock provider fixtures and disabled credentials.

## Firecrawl v2 request contract cross-check

The adapter targets the official [v2 Search endpoint](https://docs.firecrawl.dev/api-reference/endpoint/search) with web-only sources, a maximum of ten results, and a bounded millisecond timeout; it consumes `success` and `data.web[*].url`, never snippets. It targets the official [v2 Scrape endpoint](https://docs.firecrawl.dev/api-reference/endpoint/scrape) with markdown only, basic proxy, TLS verification, no actions/headers, fresh/no-cache options, and bounded response bytes/deadline. The returned source URL/final URL, status, content type, text completeness and length are validated before constructing a document.

The endpoint schema documents these request/response fields and error classes, including 429. It does not establish the current pricing/account contract; unit costs remain explicit local settings. No live API contract probe was run.
