# Manual pull request review while branch protection is unavailable

Observed October 7, 2026 at 20:23 UTC: the repository is private, and GitHub's read-only `GET /repos/nrsandoval1231-oss/gl3/branches/main/protection` returned HTTP 403 with “Upgrade to GitHub Pro or make this repository public to enable this feature.” Keep the repository private. No GitHub-enforced required checks or review rules are configured or claimed by this procedure.

Until branch protection can be enabled under the existing plan, use this manual gate for every pull request:

1. Keep the pull request in draft while implementation is in progress. Record the PR number, immutable head commit SHA and Git tree SHA, and the current target-branch head SHA when review begins.
2. The controller runs and retains all applicable backend tests, frontend tests and browser checks, type/lint checks, migration checks, dependency audits, and other packet-specific gates. For each run, record its workflow/run identity, event type, PR number, reported `head_sha`, and, for `pull_request` or `merge_group` validation, the tested merge SHA and the base SHA from which that merge candidate was formed. A successful check on a PR head alone does not prove the tested merge result; a check on a synthetic merge candidate is applicable only to that recorded head/base pair. Do not infer this relationship from a green badge or run title.
3. An independent reviewer examines the PR head commit and tree, including changed-file scope, acceptance criteria, failures, and unresolved comments. Record the review outcome and evidence against that SHA/tree. The review and CI candidate are separate evidence and must each identify their subject.
4. Resolve all review comments and inspect the pull request's review state and check conclusions. Immediately before any separately authorized merge, compare the current PR head SHA/tree with the reviewed values and compare the current target-branch head SHA with the base SHA used by the successful merge checks. If the head or tree moved, repeat affected checks and review on the new candidate. If only the base moved, create and validate a merge candidate against the new base; preserve the unchanged source review only if its head SHA/tree still match and no merge conflict changes the reviewed source tree.
5. Retain the PR number, final head SHA/tree, tested merge SHA and base SHA, workflow/run identities and conclusions, review record, and separate merge authorization with the release evidence. This is a human procedure, not a substitute claim that GitHub required or enforced the checks.

If repository plan or visibility changes later, recheck protection through GitHub and replace this manual procedure only after required rules are configured and verified. Do not change visibility or billing as part of this procedure.
