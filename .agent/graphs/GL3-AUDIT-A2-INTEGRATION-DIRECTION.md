# A2 integrated lifecycle correction — architecture direction, 2026-10-07

**Direction: CORRECT the proposed pairwise hash repair before freeze.** Ingestion stores two legitimate hashes for one current record: `Observation.content_hash` and `Interpretation.content_hash` are the semantic `_hash(record)`; `Evidence.content_hash` and `assessment.evidence_hash` bind the retrieved source/document version (`source_hash` or `_source_version_hash(record)`). Taylor's withdrawal record can have different semantic and source hashes, so requiring all four hashes equal is incorrect. But the current uncommitted pairwise change in `gl3-lifecycle-delivery-20261007` is insufficient by itself: ingestion can retain an old accepted `assessment` while updating `Interpretation.content_hash` and status for a new version. An old evidence hash would still match that assessment unless its `semantic_hash` is also checked. This is an architecture verdict on the uncommitted proposal, not acceptance of the builder candidate.

**One version-binding rule.** A lifecycle event is current only when all of these hold: its `project_id` is the projected project; `LifecycleEvent.observation_id == Interpretation.observation_id == Evidence.observation_id == Observation.id`; `Observation.content_hash == Interpretation.content_hash == assessment.semantic_hash`; `assessment.evidence_hash == Evidence.content_hash`; and, when the assessment records an evidence ID, that ID equals `LifecycleEvent.evidence_id == Evidence.id`. The project's exact `identity_key` equals the accepted assessment's bound `project_identity_key`; the source and facility/event scope are reclassified from that **current Evidence** and its linked Observation, never from a stale project asset tag or retained sibling document. Distinct semantic and source hashes are allowed only through this deterministic same-observation/accepted-assessment association. The event/state must equal the classification of the current evidence. No old A event supports B merely because a text pattern or project ID still matches.

For ordinary positive events, require an accepted current assessment: `Interpretation.status == accepted`, or preserve the repository's existing `pending`/`failed` retry behavior only when `assessment.decision == accepted` **and every binding above remains current**. A transient evaluator outage on an unchanged version may retain an accepted claim; a pending/failed replacement version with an A assessment must not. For `planning_application_withdrawn`, rejected/unknown interpretation status can still support a negative lifecycle event only when the current assessment explicitly carries `withdrawal_supported`, all version/project/evidence bindings above hold, and the ingestion path proves a unique same-article accepted need selected that project. The flag must not be inferred from a withdrawn title, similar facility name or unrelated project. Keep negative evidence and prior positives in history; project viability after withdrawal remains UNKNOWN.

**Classifier scope.** The warehouse-after-data-center failure is a real negative-scope case if the current permit record is a warehouse-only correction: a previously typed `Project.asset_type=data_center` and generic electrical-permit title must not lend a campus milestone to the new warehouse description. Then the old campus lifecycle support falls away and the card's expected WATCH transition is tested against the full canonical evaluator, not forced by test stubbing. The current narrow fallback suppression for named warehouse text is plausible but needs a counterexample: a report with a separate explicit, correctly named data-center-campus permit clause must still classify that campus clause even if another clause names a warehouse. Preserve physical construction/commissioning distinctions; a permit authorizes work but is not achieved construction.

**Required deterministic acceptance before integration.** Use realistic split semantic/source hashes in synthetic fixtures and set `assessment.semantic_hash` to the semantic digest; existing equal-hash fixtures or assessments missing this field cannot prove the live contract. Test Taylor same-observation withdrawal with distinct hashes, exact current `project_identity_key`, unique accepted same-article need, one withdrawal event/change and idempotent replay; unrelated/conflicting Taylor articles must not withdraw. Test event/interpretation/evidence observation-ID mismatch even when hashes collide; missing/wrong assessment semantic hash; missing/wrong evidence hash or recorded evidence ID; wrong project/facility; and old A assessment retained under current B semantic hash while status is pending or failed. Assert B removes A support, and a genuinely current accepted A→B→A reversion restores only the original A event without duplicate history. Test unchanged-version evaluator failure retains support only under the fully current bound assessment. Test warehouse-only correction from a previously data-center-tagged permit gives the canonical WATCH result, while an explicit independently scoped campus clause remains supported. Run Taylor/research-transition focused integration tests, lifecycle scope tests, full backend on the dedicated `*_test` DB, Ruff/mypy and retained-copy inventory; preserve raw failures and re-review the new exact head. Do not change original application data or fabricate a pass by weakening the version guard.
