## Measured condition

In disposable synthetic PostgreSQL schemas, ten draft-plus-accept fact cycles copied 32,380 browse rows at 1,620 needs and 99,980 at 5,000 needs; the windows produced approximately 153.7 MB and 500.4 MB WAL. Combined write p95 was 1,031 ms and 2,424 ms; concurrent list-read p95 was 61 ms and 133 ms, all sampled reads 200. There were only ten write samples per size, so p99 and production SLO inference are unsupported. The measured copy count is consistent with about twenty scoped generations, one for each draft and acceptance, rather than ten. Verify this by per-request generation/revision receipts before acting. Retained accepted facts, production latency, larger ingestion batches, and rollover were not measured by this script.

The first benchmark's `group_metadata_ms=0` was a classifier defect: `_publish_group_metadata` emits a `WITH ... UPDATE`. The follow-up isolated profile fixes that attribution. At 1,620 needs, one draft took 420 ms, including 107 ms copying 1,619 rows, 108 ms ANALYZE, 30 ms group metadata and 23 ms pruning. At 5,000 needs, one draft took 798 ms, including 359 ms copying 4,999 rows, 122 ms ANALYZE, 75 ms group metadata and 96 ms pruning. Each draft advanced input revision by two and published a new generation, while the profiled affected row's saved columns and generation clock boundary were identical before/after. Acceptance changed that row and warranted publication. The profile has one draft and one acceptance at each size, no competing reader, and does not establish production latency. Its lock metric still measures acquisition only, not total hold.

## One direction: CORRECT the proven draft-only publication

The measured redundant operation is draft-only browse invalidation and scoped publication. Dispatch one bounded Luna repair after RETAINED joins. Keep existing immutable generations, pointer fencing, and accepted-fact publication. The focused change is at the input trigger and clock-eligibility boundary; no row-layout or shared-row design is needed. Preserve the baseline/profile as before evidence; compare the exact repaired candidate using the same disposable fixture and concurrency, with separate batch and rollover checks.

The consumer boundary is narrow but has one required repair. Browse summary/detail projection calls `load_current_need_operator_inputs`, which selects only the latest accepted/corrected decision per version and active effective interval; `fact_digest` also uses that accepted set. Draft fact history is served separately by `/api/needs/{id}/facts` from canonical tables. Yet `clock_deadline` currently scans **all** fact effective dates, including unaccepted drafts; commercial triage evaluation also calls it. Restrict both `effective_from` and `effective_until` boundary queries to the latest accepted/corrected decisions that can enter the browse projection. This avoids claiming a draft-created clock boundary while preserving every accepted boundary. A draft remains immediately visible in fact history.

At the trigger, a newly inserted `CallFactVersion` cannot affect accepted projection until a decision exists, so suppress its INSERT invalidation only. Suppress `CallFactDecision` INSERT invalidation only for an initial draft decision that cannot replace an existing latest accepted/corrected decision. An unexpected later draft, mixed bulk statement, accepted/corrected/superseded/retracted/rejected decision, and every UPDATE/DELETE/TRUNCATE retain conservative invalidation. Ensure trigger conditions inspect the full transition set and existing history, not just an API route assumption. Keep worker and API `_refresh_saved_operator_change` calls: with no draft dirty flag/revision they return without publication; acceptance still invalidates and publishes atomically. Simply removing the API call would leave a stale revision and 503. Do not mutate an existing generation to force revision equality.

Packet after `AUDIT-RETAINED` joins: `AUDIT-PUBLICATION-1`, one Luna. Owned files only `backend/src/gridlens/persistence/browse_invalidation.py`, `backend/src/gridlens/intelligence/saved_browse.py`, the additive migration needed to install changed triggers, and focused PostgreSQL tests. `backend/src/gridlens/api/app.py` is inspection only unless the controller separately releases it after CORE/WORKSPACE integration. Exclude stored-row layout, generation pointer semantics, ingestion policy, qualification rules, production database and deployment. Base the packet on the exact integrated SHA. Retry budget two materially distinct repairs.

## Deterministic acceptance

On isolated PostgreSQL: an initial draft creation and replay must retain fact history but produce zero browse revision/generation change, including with a future effective date that would previously shorten `clock_deadline`. Accepted/corrected/retracted fact must advance revision and publish a new immutable complete generation or visibly remain pending. Test accepted effective-from/effective-until around UTC and Chicago midnight, late draft decision after an accepted one, mixed bulk decisions, direct SQL insert, UPDATE/DELETE/TRUNCATE, stale/corrected predecessors, concurrent draft/accept writers, rollback/crash, full rebuild and worker publication, source changes, and unknown writes. Verify pre-commit reads see the prior complete generation, post-commit reads see exactly the new revision, cohort tokens reject mixed pages, retained evidence digests and need qualification agree with a fresh full rebuild. The expected mechanical improvement is one generation and approximately one corpus copy avoided per draft; compare before/after per-operation WAL, copies, phase times and p95 with identical corpus/concurrency, and report no latency speedup if within noise. Run affected tests, migrations/drift, Ruff/mypy, frozen exact-candidate gates and independent review. Synthetic timings remain local evidence only.

An explicit interactive execution deadline may be considered only after per-statement/lock evidence shows unbounded request time. A Python deadline checked between SQL statements cannot interrupt one long SQL command or lock wait; any budget must preserve canonical commit, roll back only derived publication, expose pending state, and leave maintenance able to rebuild. The worker already has a 60-second cooperative budget. Do not add a timeout as a substitute for the measured optimization.
