# GL3 A5B bounded card contract direction — 2026-10-08

**Decision: MODIFY A5B's dispatch contract; dispatch only after independent A5A PASS.** Provisional A5A candidate `fb65ceb70a58c5c8d7f414a4b46cc7e3aa9e2f39` is context, not accepted by this direction. A5A chooses at most 50 commercial work groups but currently hydrates all members of each chosen group. A single group can therefore defeat A5B's public bound. `group_cards()` builds every member, unions `related_need_ids`, `related_need_states`, contacts, timeline, facts and sources, then hashes the complete merged object. A page-local subset can change disposition, reason, counts, citations and `input_hash`; it must never masquerade as a full canonical card or saved-as-of snapshot.

**Smallest safe initial contract:** keep canonical `grouped_need_ids()` and `group_cards()` as the sole commercial grouping/decision/presentation authority for groups that fit a declared resource budget. Before selected detail hydration or `/api/commercial/triage/evaluate` writes, count the selected group's members from A5A's compact global grouping. If any group exceeds the declared member cap (initially 50), return an explicit authenticated `413` bounded-card error naming the opaque canonical work-group ID, exact member count, applied cap and a stable code; do not skip the group, replace its disposition with UNKNOWN, return a partial card/count, or save a partial snapshot. For groups within that cap, preflight evidence, lifecycle, relationship, notes and saved snapshot/version payload sizes against declared per-array row and total response-byte budgets before constructing/serializing a card; if the exact complete object cannot fit, return the same explicit bound error. This preserves `CommercialTriageOut` and card item shapes when successful and gives a truthful failure when a complete authoritative card cannot be delivered. The cap is an implementation bound, not a policy threshold or claim that the work is below qualification.

The ordinary `/api/opportunities` 50-record pages and opaque *opportunity* group-member route in A5B remain independently bounded, with the packet's `group_total_filtered`, `group_loaded_on_page`, `group_complete_on_page`, matching-member flags, stable cohort token and separate record/group counts. That grouping follows the current `projectCards()` rule and is distinct from commercial `work_identity()`. An opportunity row's nested evidence/timeline/relationship arrays and exact-need detail also need explicit row/byte bounds or bounded child-page routes; a 50-record limit alone is insufficient. If an item cannot be returned completely and no child-page contract exists, return an explicit bound error before labelling it complete. Client must show partial group membership as `X of Y` and must not recompute a corpus decision from one page. Do not silently truncate nested arrays. Saved-history collection pages use stored snapshots only, retain `saved_as_of`/`metadata_only`/`not_rechecked`, and preflight stored card/version/note sizes; a too-large saved item gets a bound error or bounded snapshot-detail traversal, never live re-evaluation or a rewritten historical decision.

**Single-source seam and ownership amendment:** add only a narrow read-only keyed-group helper in `backend/src/gridlens/domain/commercial_triage.py` if required, returning the canonical `work_identity()` key with its ordered member IDs; make existing `grouped_need_ids()` delegate to it so identity, first-priority encounter, representative minimum ID and siblings remain one rule. This file is newly allowed for A5B solely for that helper and focused guard support, with no `build_card()` or `group_cards()` policy rewrite. Derive the opaque commercial group ID from the canonical key with a stable hash. A5B's app/query helper may preflight counts and bytes, then call the unchanged canonical full-group card builder only when the group fits; it must calculate page-scoped disposition/cohort counts from complete returned cards and all-eligible grouped total from the compact global cohort. Persisted `input_hash` and saved-as-of snapshots are produced only from complete canonical cards. No new qualification/grouping policy, migration, provider or styling work is authorized.

**Deterministic proof:** construct a >50-member same-work group whose last member reverses the merged disposition, and place it across the 50-group/page boundary. Verify the commercial route and evaluate return the declared bound error before detail hydration/write, with exact group ID/count; no partial card, false page count or snapshot persists. Test one <=50-member group with conflicting siblings and cross-member facts, sources and lifecycle: returned disposition, arrays, `input_hash`, representative and counts match the full-list oracle exactly. Add one member with >budget evidence/history and a saved snapshot with >budget versions/notes: responses are explicitly bounded, saved data unchanged, no live re-evaluation. For `/api/opportunities`, test 50-record pages, one >50-member opportunity group, nested oversized item, stable cohort tokens, group traversal without duplicates, accurate complete/partial flags and client `X of Y` display. Validate response bytes and peak allocation under these fixtures, OpenAPI/client shape, auth, browser behavior and the existing A5B exact-candidate gates. If a bounded canonical streaming merge is later required to serve oversized commercial cards, it needs a separate packet and parity proof; A5B must not silently approximate it.
