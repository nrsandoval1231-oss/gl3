# GL3 A5B filter contract supplement — 2026-10-08

**Direction: MODIFY the active A5B packet and CONTINUE within its browse/client ownership.** This is a concrete grammar for the PRD 31 filters already required by `GL3-AUDIT-A5B.md`; it is not a new qualification, grouping or visual initiative. The builder applies it to the current A5B candidate only after binding to the accepted A5A summary. Existing `tier`, `search`, `decision`, `limit`, `offset` and `cohort_token` remain. Unsupported parameter names/values must receive explicit 422 with a supported-values/semantics message, not be silently ignored by FastAPI. Keep request lengths and decimal/date parsing bounded.

| Parameter | Accepted values and exact meaning | Canonical authority |
| --- | --- | --- |
| `geography` | `UNKNOWN` for null/blank `Project.location`; otherwise an exact NFKC/whitespace/casefold match to a displayed `Project.location` value. Dynamic values are accepted; unmatched valid values return an empty cohort. No state inference from source coverage or a free-text city guess. | Current matched project's location; preserve nonmapped strings as selectable values. |
| `industry` | `UNKNOWN` for null/blank/`unknown`; otherwise exact normalized `Project.asset_type`, including uncommon stored values. Never use a source registry's vertical/industry label as a project fact. | Per-record project asset type already displayed by opportunity/triage. |
| `activity` | `UNKNOWN` for null/blank; otherwise exact normalized `PowerNeed.activity_key`, no substring or sibling-project substitution. | Exact need activity. |
| `timing` | `KNOWN` when the canonical effective qualification has a nonempty, non-Unknown need-specific `start_window`; `UNKNOWN` otherwise. This means a supported timing value exists, not that the date is precise or the project will start then. Date-bound parameters are unsupported until a canonical typed interval exists; reject them with 422. | A5A `effective_need_qualification`, never stored stale `PowerNeed.start_window` or project lifecycle date as a substitute. |
| `mw_status` | `KNOWN` only when canonical effective **activity-specific required MW** parses to a finite nonnegative exact point/range; `UNKNOWN` otherwise. A Lead's remaining gap is a different quantity and must not silently replace demand. | Effective qualification plus the existing `commercial_presentation` exact quantity parser. |
| `mw_min`, `mw_max` | Optional finite nonnegative decimal **MW** bounds, inclusive; when both present require min <= max. A need with effective demand interval `[low, high]` matches if it overlaps the requested interval (`high >= mw_min` and `low <= mw_max`). Unparseable/qualified prose/ambiguous units are `UNKNOWN`, never zero and never match a numeric range. `mw_status=UNKNOWN` with numeric bounds is 422. | Reuse/factor the exact unit/range parsing already used by `commercial_size_status`; do not create a second MW interpretation rule. |
| `priority_segment` | Integer `0..8`, exact first element of canonical `_priority()` tuple, with server-supplied label for the existing segment meaning. Filtering does not replace `/api/opportunities` updated-at order. Any unsupported priority alias/band is 422; do not invent high/medium/low thresholds. | A5A `PriorityInputAccumulator`/`_priority()` parity result. |
| `status` | `UNKNOWN` only while browse has no canonical persisted per-need pursuit-workflow status; it selects records whose workflow status is unavailable. Other values return 422. Signal `decision=SHOW/REVIEW/HOLD`, commercial disposition and a call-note outcome are distinct and must not be relabeled as workflow status. Add supported statuses only after an accepted authority/contract exists. | No current per-need workflow-status field in `PowerNeed`/`Pursuit`; explicit unavailable value. |

Normalize enum spelling once and publish it in OpenAPI/client; do not treat malformed numeric values as `UNKNOWN`. `tier` is effective need tier, independent of `status` and Signal `decision`. Expose selectable `UNKNOWN` for missing location, asset type, activity, timing and MW; preserve unsupported/nonmapped geography records in browse. For a future state lens, `state`/geocoded geography remains 422 until an authoritative project-to-state mapping is accepted. The UI may list exact available location/industry/activity values from server-filter metadata or bounded aggregate facets; it must not infer statewide coverage from source labels.

Group totals/complete flags use the filtered group membership, not an unfiltered project size. The cohort token includes every normalized filter value, group identity/order and relevant version, so a changed filter/snapshot yields 409 on an echoed token. Use the identical grammar, normalization, membership and token on record pages, group-member traversal and CSV. Exact-need detail remains complete and need-scoped; when opened from a filtered page, validate supplied cohort/scope and report stale or out-of-scope explicitly rather than silently substituting a sibling. Client and Back restore all filter values, selected need and offset; counts/featured record/empty state reflect that same server cohort.
