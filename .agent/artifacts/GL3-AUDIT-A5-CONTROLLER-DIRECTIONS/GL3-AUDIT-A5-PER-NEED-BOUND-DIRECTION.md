# GL3 A5A per-need bound direction — 2026-10-08

**Direction: CONTINUE the existing bounded-summary correction with a narrow internal-reducer amendment.** The active A5A Luna has measured frozen-corpus parity and 67 SQL / 3.292 s / 18.95 MB cold with 128-need batches, historical date SQL aggregation, streamed lifecycle rows and no brief ORM rows in the summary. This is progress, not an accepted candidate: `links_by_need` still retains every current `Observation`/`Evidence`/`Interpretation` ORM tuple for a need; an arbitrarily large need defeats the bound despite the current corpus maximum of three links per need.

**Authorized internal seams, within A5A ownership:** `api/app.py` summary orchestration; narrow iterator/accumulator variants inside `ingestion/service.py` for `_need_has_current_support` and `_current_need_claims`/`effective_need_qualification`; a narrow `intelligence/project_state.py` research summary accumulator; and a narrow `domain/commercial_triage.py` priority/group-key feature accumulator. Existing public callable behavior and canonical policy must remain the source of truth. The earlier optional `intelligence/briefs.py` preload remains limited to the separate brief direction. Tests may cover these seams. No change to `lifecycle_service.py`, schema, API/client shape, qualification/admission rules, source/provider behavior, or persisted cache is authorized.

Stream current linked rows in the canonical `Evidence.observed_at DESC, Evidence.content_hash DESC` order, with deterministic continuation across chunks, and fold them instead of appending ORM tuples to `links_by_need`. Preserve the first **currently supporting** evidence used by `work_identity()`; it may differ from the first linked row. Call the existing version binding and `admitted_from_source()` rules on each row, and preserve observation deduplication for qualification. `_current_need_claims` requires the canonical sort winner and contradiction detection across *all* admitted current claims: keep the best sort key/claim and compact sets or flags for distinct demand, start, duration, gap inputs, qualification-conflict and qualification-version presence. Do not let a later chunk erase an earlier conflict or choose a stored tier. Retain only the minimal canonical assessment fields needed for floor/action checks and selected summary identity. If any output field genuinely requires an unbounded set of claim values, document that irreducible requirement and return for controller recovery rather than silently truncating it.

For research, `current_research_state()` validation is exact need-bound (`target_need_id`, claim need/activity/evidence/hash/quote); `project_claim_state()` conflicts are computed within that need. A summary-only accumulator may keep field value/status and the age/persistence facts needed to apply those same rules and `qualification_veto()`. Full claim provenance remains on the selected detail path. For priority, preserve the existing `_phase_flags()` and `_priority()` semantics by accumulating their exact text predicates per **supporting evidence item**, including the item-local `commissioning.{0,40}` scope expression; do not concatenate across evidence boundaries or replace it with broad keyword flags. Keep the max of every retained `published_at or event_date` used in the original priority, the first supporting citation identity, and compact `(priority tuple, need ID, work key, project ID)` records sufficient for global first-encounter grouping and all-eligible totals. These records scale with the number of eligible needs/groups; full evidence/history ORM retention does not. Selected group members are hydrated through the existing full projection only after global page selection.

Project-level `ProjectLifecycle.current_state` and all canonically supported lifecycle event type/state inputs must still be folded for phase priority and Taylor withdrawal, including a project spanning need batches. Per-need Taylor identity conflict and signal display decision/research veto remain exact. Stream lifecycle rows through `lifecycle_event_supported()` and reduce only the fields used in summary; preserve full timeline in selected detail. If any project or need has many rows, peak retained ORM rows must remain bounded by the fetch chunk, not by that entity's total links/events.
